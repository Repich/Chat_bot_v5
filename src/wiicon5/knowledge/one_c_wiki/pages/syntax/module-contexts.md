# Контексты выполнения модулей

## Коротко

Контекст выполнения модуля — это набор доступных имен, свойств, методов, объектов и правил исполнения. Встроенный язык нельзя понимать отдельно от контекста: доступность кода зависит от места модуля, режима запуска и клиент-серверной стороны.

## Когда используется

- При ошибках вида «метод объекта не обнаружен» или «переменная не определена» после переноса кода.
- При разделении клиентского и серверного кода.
- При проектировании общих модулей и модулей форм.
- При выборе, где объявлять экспортную процедуру.

## Как работает

В главе выделяются два базовых уровня:

- глобальный контекст — то, что доступно шире конкретного модуля;
- локальный контекст — имена и объекты конкретного модуля.

Локальный контекст складывается из переменных модуля, процедур, функций, параметров, локальных переменных и доступных объектов платформы для данного места исполнения. Контекст формы отличается от контекста объекта, а серверный контекст отличается от клиентского.

## Типовые ошибки

- Перенести процедуру из формы в общий модуль и оставить обращения к элементам формы.
- Вызвать серверный объект из клиентской процедуры без явного серверного вызова.
- Считать экспорт из общего модуля универсальной глобальной функцией без учета свойств общего модуля.

## Примеры

```bsl
&НаКлиенте
Процедура КомандаВыполнить(Команда)
    // Здесь доступен клиентский контекст формы.
    ОбновитьОтображение();
КонецПроцедуры
```

Если `ОбновитьОтображение()` использует серверные объекты напрямую, код придется разделить на клиентскую и серверную части.
