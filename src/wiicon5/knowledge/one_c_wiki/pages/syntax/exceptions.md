# Исключения

Status: `answer-ready`.

## Коротко

Исключение в 1С — это ошибка времени выполнения, которая прерывает текущий участок кода и может быть перехвачена конструкцией `Попытка ... Исключение ... КонецПопытки`. Исключение можно также сгенерировать из кода оператором `ВызватьИсключение`.

В 1С нельзя объявлять собственные типы исключений как отдельные классы, но можно вызвать исключение с текстом, категорией, кодом, дополнительной причиной и исходной причиной ошибки.

## Когда используется

Использовать `Исключение` стоит в случаях, когда операция может аварийно завершиться и есть понятный способ обработать этот сбой:

- внешние ресурсы: COM, файлы, сеть, web-сервисы, внешние компоненты, Excel;
- операции с базой данных, которые могут упасть из-за блокировок, ошибок СУБД или состояния данных;
- интеграции и обмены, где нужно записать диагностическое сообщение и корректно остановить сценарий;
- бизнес-запреты, которые должны именно прервать выполнение операции, например проведение документа невозможно;
- добавление контекста к низкоуровневой ошибке перед передачей ее выше;
- асинхронные операции, если исключение перехватывается в месте `Ждать`.

## Синтаксис обработки

```bsl
Попытка
    // Код, который может вызвать ошибку времени выполнения
Исключение
    // Обработка ошибки
КонецПопытки;
```

Если в блоке `Попытка` возникает ошибка времени выполнения, выполнение текущего оператора прерывается и управление переходит в блок `Исключение`. После выполнения блока `Исключение` управление продолжается после `КонецПопытки`, если исключение не было вызвано повторно.

Конструкции можно вкладывать. Если внутри обработчика выполнить `ВызватьИсключение;`, платформа ищет внешний обработчик. Если внешнего обработчика нет, ошибка обрабатывается системно и выполнение модуля прекращается.

## Вызов исключения

Простой вариант:

```bsl
ВызватьИсключение "Документ не может быть проведен";
```

Функциональный вариант позволяет указать категорию, код, дополнительную причину и исходную причину:

```bsl
ВызватьИсключение(
    "Документ не может быть проведен",
    КатегорияОшибки.ОшибкаКонфигурации,
    "ERR.DOCS.0001",
    "Клиенту запрещена отгрузка"
);
```

Категорию желательно указывать, когда ошибка формируется из прикладного кода и должна быть понятнее пользователю. Категория влияет на отображение ошибки.

## Типовые сценарии

### Показать понятную ошибку и остановить сценарий

```bsl
Если КлиентЗаблокирован Тогда
    ВызватьИсключение "Отгрузка запрещена: клиент заблокирован";
КонецЕсли;
```

Такой вариант уместен, если продолжение операции приведет к некорректному состоянию.

### Обработать необязательную внешнюю операцию

```bsl
Попытка
    Excel = Новый COMObject("Excel.Application");
Исключение
    Предупреждение(ОписаниеОшибки());
    Возврат;
КонецПопытки;
```

Здесь ошибка внешнего приложения не должна ломать весь сеанс, но должна остановить текущую ветку формирования отчета.

### Зафиксировать контекст и передать ошибку выше

```bsl
Попытка
    ВыполнитьОбменДанными();
Исключение
    ЗаписьЖурналаРегистрации(
        "ОбменДанными",
        УровеньЖурналаРегистрации.Ошибка,
        ,
        ,
        ОписаниеОшибки()
    );
    ВызватьИсключение;
КонецПопытки;
```

Так лучше, чем молча проглотить ошибку: диагностический след остается, а вызывающий код узнает, что операция не выполнена.

### Повторить транзакцию после ошибки базы данных

Если ошибка базы данных произошла внутри транзакции, такую транзакцию нельзя продолжать или фиксировать. Ее нужно отменить и, если это действительно нужно, начать попытку заново.

```bsl
Записано = Ложь;

Пока Не Записано Цикл
    НачатьТранзакцию();
    Попытка
        Данные.Записать();
        ЗафиксироватьТранзакцию();
        Записано = Истина;
    Исключение
        ОтменитьТранзакцию();
    КонецПопытки;
КонецЦикла;
```

Важно: такой retry допустим только если есть уверенность, что `НачатьТранзакцию()` действительно начинает новую транзакцию, а не увеличивает счетчик уже открытой транзакции. Во многих случаях лучше показать ошибку пользователю и дать ему решить, повторять ли операцию.

### Асинхронный код

Исключение асинхронной функции перехватывается не в месте получения обещания, а в месте `Ждать`.

```bsl
ОбещаниеФайлов = НайтиФайлыАсинх(Каталог, "*.xml");

Попытка
    Файлы = Ждать ОбещаниеФайлов;
Исключение
    Сообщить("Ошибка поиска файлов: " + ОписаниеОшибки());
КонецПопытки;
```

Если асинхронная процедура завершилась исключением и его не обработали внутри нее, перехватить это исключение за пределами процедуры нельзя.

## Когда не использовать

- Для обычного ветвления, где достаточно `Если ... Тогда`.
- Для штатной валидации формы, если можно показать сообщение и не бросать ошибку.
- Чтобы скрыть техническую ошибку и продолжить работу как будто все успешно.
- Чтобы оборачивать большой блок кода без понимания, какие ошибки допустимы.
- Чтобы продолжать транзакцию после ошибки базы данных.
- Чтобы ловить ошибку только ради пустого блока `Исключение`.

## Что нельзя перехватить

Конструкция `Попытка ... Исключение` не перехватывает:

- ошибки компиляции модулей встроенного языка во время исполнения;
- ошибки времени исполнения в обработчиках `ПередЗакрытием()` и `ПриЗакрытии()` управляемой формы.

Такие ошибки отображаются системой и приводят к прекращению выполнения встроенного языка.

## Информация об ошибке

Для диагностики используются:

- `ОписаниеОшибки()` — краткий текст текущей ошибки;
- `ИнформацияОбОшибке()` — объект с подробной информацией об ошибке;
- представления ошибки из библиотек обработки ошибок, если они используются в конфигурации.

Нужно учитывать, что попадание во вложенный обработчик исключения может привести к потере информации о родительском исключении. Если нужно сохранить причинно-следственную связь, передавайте исходную ошибку как причину в функциональной форме `ВызватьИсключение(...)`.

## Типовые ошибки

- Проглотить исключение пустым блоком и оставить систему в неопределенном состоянии.
- После ошибки базы данных внутри транзакции пытаться продолжить ту же транзакцию.
- Повторно вызывать операцию записи в цикле внутри уже испорченной транзакции.
- Перехватывать исключение асинхронной функции не там, где выполняется `Ждать`.
- Использовать исключение вместо понятной проверки бизнес-условия.
- Показывать пользователю низкоуровневый технический текст без прикладного контекста.
