# Проверка запросов к документам и табличным частям

status: `answer-ready`

## Коротко

Документ отражает прикладное событие во времени. Документы обычно имеют реквизиты, табличные части и при проведении формируют движения по регистрам.

## Правила проверки

1. Для списка документов использовать источник `Документ.<ИмяДокумента> КАК <Алиас>`.
2. Для строк табличной части использовать источник `Документ.<ИмяДокумента>.<ИмяТабличнойЧасти> КАК <Алиас>`.
3. При чтении табличной части нужно понимать связь строки с документом через поле ссылки на документ; если ответ должен показывать документ и строки, запрос должен явно выбирать или соединять эту связь.
4. Для запросов "за период" по документам нужно фильтровать дату документа через стандартное поле даты документа.
5. Если пользователь спрашивает учетный итог, остаток, оборот, долг или выручку, правильный источник часто не документ, а регистр, который документ заполняет при проведении.

## Типовые ошибки агента

- Искать учетные итоги в табличных частях документов вместо регистров.
- Читать табличную часть как самостоятельный бизнес-объект без связи с документом.
- Делать широкий список документов без периода, лимита или уточнения пользователя.

## Источники

- 1Ci Knowledge Base, `Documents`: документы записывают данные в регистры; табличные части документа могут использоваться для формирования движений.
