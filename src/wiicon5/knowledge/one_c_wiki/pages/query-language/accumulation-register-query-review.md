# Проверка запросов к регистрам накопления

status: `answer-ready`

## Коротко

Регистр накопления хранит движения и итоги ресурсов в разрезе измерений. Запрос к регистру накопления нужно строить по-разному в зависимости от источника:

- таблица движений `РегистрНакопления.<Имя>` возвращает записи регистра;
- виртуальные таблицы `Остатки`, `Обороты`, `ОстаткиИОбороты` возвращают рассчитанные представления по итогам и движениям.

## Правила проверки

1. Если запрос читает таблицу движений `РегистрНакопления.<Имя> КАК <Алиас>`, а не виртуальную таблицу, по умолчанию нужно учитывать только активные записи: добавить условие `<Алиас>.Активность`.
2. Поле `Активность` относится к записи регистра. Оно не является обычным измерением или ресурсом виртуальной таблицы `Остатки`, `Обороты` или `ОстаткиИОбороты`; не нужно добавлять `<Алиас>.Активность` к алиасу виртуальной таблицы.
3. Для виртуальных таблиц отборы по периоду и измерениям лучше передавать параметрами виртуальной таблицы, а не фильтровать широкий результат снаружи через `ГДЕ`.
4. У виртуальных таблиц имена ресурсных полей строятся от имени ресурса:
   - `Остатки`: `<Ресурс>Остаток`;
   - `Обороты`: `<Ресурс>Оборот`, а также поля прихода/расхода в зависимости от вида регистра;
   - `ОстаткиИОбороты`: начальный остаток, приход, расход, оборот и конечный остаток.
5. Фильтр по рассчитанному ресурсу, например `<Алиас>.КоличествоОстаток <> 0`, допустим в `ГДЕ`, если это именно фильтр результата, а не отбор исходных измерений.

## Типовые ошибки агента

- Суммировать таблицу движений регистра накопления без `<Алиас>.Активность`.
- Добавлять `Активность` к алиасу виртуальной таблицы.
- Использовать ресурс `Количество` в виртуальной таблице `Остатки` вместо `КоличествоОстаток`.
- Фильтровать виртуальную таблицу по измерениям только во внешнем `ГДЕ`, хотя это ухудшает производительность и иногда меняет смысл для отдельных типов виртуальных таблиц.
