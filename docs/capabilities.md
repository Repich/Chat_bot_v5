# Возможности

## Что Агент Умеет Сейчас

### Общий Диалог

- Отвечает на базовые вопросы вроде "кто ты" и "что ты умеешь".
- Отсекает явно нерелевантные вопросы.
- Хранит контекст внутри сессии.
- Использует предыдущие артефакты для follow-up вопросов.
- Задает уточняющие вопросы, если пользовательская формулировка допускает
  несколько бизнес-смыслов.

Пример корректного уточнения:

```text
Пользователь: Кто нам должен за последнюю отгрузку и сколько?
Агент: находит последнюю отгрузку и уточняет, нужна сумма документа или
       фактическая задолженность.
Пользователь: Покажи сумму отгрузки по документу
Агент: отвечает из сохраненного ClarificationRequest без нового запроса к MCP.
```

### Работа С 1С Через MCP

- Получает метаданные из подключенного MCP-сервера 1С.
- Выполняет read-only запросы 1С через MCP.
- Переиспользует `_objectRef`, возвращенные MCP, вместо строкового поиска по
  представлению.
- Нормализует строки MCP для отображения и трассировки.

### Навыки И Планы

- Загружает атомарные skill contracts из `skills/atomic`.
- Строит планы по outputs навыков и требуемым typed artifacts.
- Выполняет детерминированные presentation и transform skills.
- Фиксирует skill gap, если текущий граф навыков не может произвести нужный
  артефакт.
- Использует bindings из `skills/bindings`, чтобы сопоставить semantic skill с
  конкретной конфигурацией 1С.

Текущие seed skills:

- получение складов;
- получение остатков;
- получение списка документов по типу и периоду;
- подсчет документов перемещения по дням;
- универсальный подсчет сущностей;
- детерминированный рендер таблиц и списков.

### Query Synthesis

Если навыков недостаточно, агент может:

- попросить LLM подобрать термины поиска метаданных;
- получить подходящие metadata objects;
- попросить LLM построить read-only запрос на языке запросов 1С;
- проверить безопасность запроса;
- проверить типовые ошибки языка запросов 1С;
- выполнить запрос через MCP;
- расширить поиск метаданных после ошибки или недостаточного результата;
- проверить, что результат действительно отвечает на вопрос;
- сформировать финальный ответ.

### Learned Skills

Успешные шаблоны synthesized query могут сохраняться в `skills/learned`.
В текущем репозитории есть пример learned skill для финансовых показателей:
выручка и прибыль по периоду.

Обучение специально сделано консервативным: успешный ответ не считается
автоматически универсальным навыком, если у него нет понятной переиспользуемой
формы.

### Web-Клиент

Локальный web-клиент умеет:

- отправлять сообщения;
- отправлять по Enter и вставлять перенос строки по Shift+Enter;
- держать поле ввода видимым в длинном диалоге;
- показывать текущую версию;
- восстанавливать историю сессии после перезагрузки страницы;
- показывать backend/frontend history;
- мигать заголовком вкладки, если пришел ответ, пока вкладка не активна.

## Текущие Ограничения

- Это alpha-версия. Архитектура еще проверяется на реальных бизнес-вопросах.
- Агент не гарантирует корректный запрос 1С для любого объекта любой
  конфигурации.
- Текущий каталог навыков намеренно небольшой. Он нужен для проверки
  архитектуры, а не для полного покрытия WIICON.
- Часть сценариев зависит от того, насколько MCP возвращает пригодные
  метаданные.
- Некоторые learned skills могут быть специфичны к метаданным, найденным во
  время локального тестирования.
- Web-клиент предназначен для тестирования и диагностики.
- Память диалога локальна для процесса сервиса, если конкретный запуск не
  включает отдельную персистентность.
- Агент не должен использоваться для операций изменения данных 1С.

## Как Выглядит Правильное Поведение

Для вопроса по бизнес-данным агент должен:

- учитывать полный контекст диалога;
- проверить существующие навыки до создания нового пути;
- не подгонять вопрос под нерелевантный навык;
- получить или проверить метаданные перед использованием объектов и полей 1С;
- выполнять только read-only запросы;
- отвергать недостаточные промежуточные результаты;
- задавать уточнение вместо угадывания бизнес-смысла;
- возвращать короткий ответ на основе реальных данных MCP;
- оставлять trace, по которому можно воспроизвести решение.
