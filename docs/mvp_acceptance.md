# Критерии MVP самообучения

MVP считается достигнутым не по отдельному удачному ответу, а по сквозному циклу:

1. На незнакомый вопрос агент строит read-only запрос по подтвержденным метаданным.
2. Результат проходит проверку достаточности относительно исходного вопроса.
3. Агент сохраняет полный выполненный запрос, параметры, зависимости метаданных и семантический контракт.
4. На семантически совместимый вопрос с другими значениями фильтров агент использует созданный навык.
5. На похожий, но несовместимый вопрос агент не использует этот навык и возвращается к синтезу.

## Обязательные инварианты

- Нельзя активировать навык без успешного MCP-выполнения именно сохраняемого запроса.
- Нельзя активировать навык без положительной проверки достаточности результата.
- Нельзя активировать или выполнить навык при неопределенном fingerprint конфигурации.
- Сумма, среднее, количество, минимум и максимум не взаимозаменяемы.
- Рейтинг, зерно результата, обязательные размерности и фильтры входят в контракт.
- Ненулевой результат не считается правильным только потому, что в нем есть строки.
- Ошибка LLM-проверки достаточности закрывает путь к ответу и обучению.
- Навык другой конфигурации 1С не выполняется.
- Старые навыки без контракта версии 2 находятся в карантине и не загружаются.

## Измеримые пороги

Для набора `evaluation/mvp_cases.json`:

- cold answer rate: не ниже 80%;
- warm answer rate: не ниже 90%;
- reuse созданного навыка на положительных парах: не ниже 70%;
- false reuse на отрицательных парах: 0%;
- необработанные исключения: 0;
- каждый ответ и каждое решение learning gate имеют trace.

Порог ниже 100% для cold/reuse допускает ошибки внешней модели на этапе alpha, но false reuse не допускается: лучше повторный синтез, чем уверенный неверный ответ.
Для отрицательной пары fail-closed отказ после перехода к синтезу считается безопасным результатом, но продолжает снижать общий `warm answer rate`. Итоговый `ok` отчета вычисляется по указанным порогам, нулевому false reuse и отсутствию исключений, а не по требованию 100% успешных отдельных кейсов.

## Запуск

Изолированный прогон не изменяет рабочие learned skills. Для каждой cold/warm пары он создает отдельный временный bot root и копирует только bot config и onboarding index, поэтому навыки одной пары не влияют на другую:

```bash
python3 scripts/run_mvp_evaluation.py
```

Windows:

```cmd
scripts\run_mvp_evaluation.cmd
```

Отчет и трассы сохраняются в `bot_instances/local/evaluation/results/`.

## Решение о выпуске

Релиз-кандидат MVP допускается только после:

1. полного unit/integration test suite;
2. успешного прогона положительных и отрицательных semantic-contract тестов;
3. isolated MVP evaluation на доступных LLM и MCP;
4. ручной проверки минимум пяти cold/warm пар консультантом 1С;
5. перезапуска сервиса и подтверждения повторного использования навыка после рестарта.
