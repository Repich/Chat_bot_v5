5.0.0-alpha.26
- Corrected the alpha.25 list-parameter handling after live MCP validation: 1C expects IN-list parameters as В (&Параметр), not В &Параметр.
- Added query postprocessing that moves single list-parameter filters from accumulation balance virtual table arguments, such as Остатки(, Склад В (&Склады)), into an external WHERE clause by the source alias.
- Added regression coverage for the exact MCP failure form Остатки(, Склад В &РозничныеСклады) and for the canonical parenthesized form.

5.0.0-alpha.25
- Normalized 1C IN-list syntax for single array parameters generated by query synthesis: В (&Параметр) is rewritten to В &Параметр before validation, reference resolution, and MCP execution.
- Extended reference parameter parsing to recognize both В (&Параметр) and В &Параметр inside accumulation virtual table conditions.
- Added regression coverage for the syntax form that caused MCP to reject resolved warehouse-list parameters.

5.0.0-alpha.24
- Reference resolution now handles empty list parameters on reference fields inside virtual table conditions, resolving values such as Склад В (&РозничныеСклады) through MCP before the empty-list guard rejects the query.
- Query synthesis now performs safety validation and reference resolution before the empty-list guard, so resolvable empty reference lists can be repaired while unresolved ones are still blocked before the main MCP query.
- Added regression coverage for resolving empty reference lists in accumulation virtual table conditions.

5.0.0-alpha.23
- Extended semantic query review so top/max product stock questions are detected from the original user text and intent, even if the LLM goal decomposition omits an AggregateTable artifact.
- Rejected row-level ПЕРВЫЕ 1 stock-balance queries for top/max product questions when they do not aggregate to product grain with СУММА and СГРУППИРОВАТЬ ПО.
- Added regression coverage for the live failure mode where the decomposed goal only requested StockBalanceTable but the user asked for the product with the largest balance.

5.0.0-alpha.21

5.0.0-alpha.20
- Rejected plain string parameters and string-list parameters for reference fields inside accumulation virtual table conditions, such as Остатки(, Склад = &Склад), so query synthesis must resolve references or use verified reference attributes before MCP execution.
- Extended regression coverage for the retail top-stock repair path to catch string warehouse parameters inside virtual table conditions.

5.0.0-alpha.19
- Fixed 1C query source parsing for accumulation virtual tables whose parameters contain nested subqueries, so the reviewer validates both the main register source and nested reference sources.
- Added goal-aware semantic query review for top/max stock-style aggregate questions: a query over balances scoped by multiple warehouses must aggregate to product grain with SUM and GROUP BY instead of returning the first register row.
- Strengthened query synthesis regression coverage so repair after an empty reference-list parameter must preserve the original warehouse-type filter and cannot downgrade a top/max question to an ungrouped row-level query.
- Stopped treating count_entities as the nearest producer for non-count AggregateTable goals such as max/top/ranking questions.

5.0.0-alpha.18
- Tightened skill composition so a plan cannot ignore required artifacts from the decomposed goal: if the goal requires an AggregateTable, rendering another available table is no longer accepted as a complete plan.
- When choosing a concrete artifact for an abstract presentation input, the composer now prefers the latest matching required artifact, which helps route final answers to the actual target artifact instead of an intermediate helper table.
- Added regression coverage for a stock-balance question that also requires ranking/aggregation.
