5.0.0-alpha.86
- Learned skills переведены на SemanticSkillContract v2 и semantic_query_template: сохраняется полный успешно выполненный запрос с JOIN, WHERE, GROUP BY, ORDER BY и проверенными параметрами без lossy-реконструкции.
- Skill matching теперь fail-closed различает operation, measure, aggregation, grain, dimensions, ranking, filter roles, fixed values и result columns; сумма/среднее, максимум/минимум и список/количество не взаимозаменяемы.
- Добавлен learning gate: read-only safety, актуальная schema, согласованность query/contract, достаточный результат, exact execution evidence, positive/negative semantic probes, metadata dependencies и resolved configuration fingerprint.
- Результат переиспользованного навыка проходит тот же sufficiency reviewer, что и query synthesis; runtime health обновляется только после финального semantic review.
- Skill execution стал транзакционным: промежуточные артефакты не попадают в память до принятия результата.
- Старые active learned skills без SemanticSkillContract v2 автоматически перемещаются в сохраняемый quarantine и исключаются из registry.
- WIICON5_CONFIG_FINGERPRINT по умолчанию работает в режиме auto; пустые метаданные дают unresolved и блокируют обучение/исполнение learned skills.
- Торговые semantic review и metadata ranking rules изолированы в domain pack trade_ru и не применяются к universal bot profile.
- Узкие text classifiers детализации и агрегации заменены структурированным semantic_contract от decomposition LLM.
- Добавлен изолированный cold/warm MVP evaluation runner, пять положительных и пять отрицательных пар, метрики reuse/false reuse и документ с критериями приемки MVP.
- Fixed filter values в semantic contract сравниваются по строгому нормализованному равенству, поэтому отрицательная проба больше не принимает значение с совпадающей подстрокой; значения текущих product/warehouse/year-фильтров удаляются из subject_terms.
- MVP evaluation различает переиспользование нового learned skill и корректное переиспользование уже существующего seed/learned skill, не требуя бессмысленного повторного обучения.
- Семантические роли сущностей нормализуют структурные суффиксы *_name, *_ref и *_reference без объектных классификаторов; warehouse_name и warehouse теперь совместимы так же, как любые другие entity-роли.
- Каждый cold/warm evaluation case запускается с отдельным bot root; исключение одного сценария записывается в отчет и не прерывает весь прогон. Ranked learning gate покрыт регрессионным тестом.
- Metadata dependency contract различает шапку документа, табличную часть и виртуальную таблицу регистра; поля проверяются по фактической форме источника, а не только по базовому объекту.
- Measure matching сравнивает содержательные токены: сумма документа не совместима с суммой задолженности только из-за общего слова «сумма».
- Sufficiency review fail-closed отклоняет неразличимые одинаковые строки как признак потерянного зерна или агрегации; stock balance без детализации агрегируется по выводимому складскому зерну.
- Итоговый флаг MVP evaluation рассчитывается по опубликованным порогам cold/warm/reuse при нулевом false reuse и отсутствии исключений; отрицательный сценарий может безопасно завершиться без ответа, но не неверным навыком.
- Query postprocessor автоматически устраняет общую коллизию, когда LLM одинаково назвала alias источника и выходную колонку: переименовывается только источник и все его dereference, выходной контракт сохраняется.
- Subject matching проверяет все смысловые квалификаторы, не представленные measure/result/grain: слово «задолженность» больше нельзя проигнорировать только потому, что остальные слова совпали с навыком суммы документа.
- Для табличной части verified nested schema родительского документа имеет приоритет над отдельной heuristic/hint записью onboarding; это сохраняет fail-closed trust policy без ложного отказа корректного learned query.
- Если decomposition не заполнила original_question, агент восстанавливает его из business goal. Фактическая операция learned query берется из формы SELECT; list может удовлетворить lookup, но одиночный lookup не подменяет list.
- Непараметризованный objectRef допускается как безопасная фиксированная константа generalized skill только при явном двусторонне совпавшем subject qualifier; навык «розничные цены» не подходит вопросу без вида цены или с другим видом.
- Локальные evidence, quarantined skills, evaluation results и diagnostic bundles исключены из Git.
- Полный regression suite расширен тестами semantic compatibility, full query preservation, learning gate, quarantine, fail-closed sufficiency, post-reuse health и MVP evaluation.
