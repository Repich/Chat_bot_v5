5.0.0-alpha.9
- Extracted clarification resolution into a dedicated policy layer so AgentOrchestrator no longer contains the document-amount follow-up scenario.
- Added BotInstanceConfig/BotInstanceContext and moved general/out-of-scope answer texts plus baseline markers into bot instance/domain policies.
- Split query/decomposition prompts into core, 1C rules, safety rules, and optional domain packs; moved trade/WIICON hints out of core prompts.
- Added pluggable metadata term expansion policies so trade-specific expansions are controlled by domain packs.
- Changed newly learned skills from verified to candidate, writing them under learned/candidates with evidence and metadata dependency contracts.
- Added config fingerprint support, including WIICON5_CONFIG_FINGERPRINT=auto, learned skill fingerprint checks, and runtime metadata dependency contract checks.
- Added regression tests for bot instance loading, clean domain packs, learned skill lifecycle, config fingerprint computation, and metadata contract failures.

5.0.0-alpha.7
- Made clarification prompts more human-readable by summarizing the found partial result as a sentence instead of a raw markdown table.
- Added deterministic resolution for follow-up answers to a ClarificationRequest when the user selects the document amount option.
- Prevented the agent from issuing a new 1C query for "show the shipment amount by document" when the amount is already present in the pending clarification artifact.
- Added regression tests for resolving "Покажи сумму отгрузки по документу" from the saved clarification context.

5.0.0-alpha.5
- Added a clarification state for ambiguous business metrics: when a question can mean either a document amount or an accounting balance, the agent asks the user instead of silently choosing.
- Query synthesis now returns source=needs_clarification through the orchestrator and stores a ClarificationRequest artifact with the partial MCP result for follow-up turns.
- Added metadata repair after genuinely insufficient results while avoiding repair calls for normal multi-step intermediate results.
- Expanded customer/debtor metadata search vocabulary toward РасчетыСКлиентами and РасчетыСКлиентамиПоДокументам.
- Added regression tests for ambiguous "кто нам должен за последнюю отгрузку" behavior and customer debt metadata search.

5.0.0-alpha.4
- Added result sufficiency review for synthesized 1C queries: a non-empty MCP result is no longer treated as final unless it covers the requested facts.
- Added debt-specific sufficiency rules: document amount is not accepted as debt, while an empty returned debt metric can be answered as no debt found for the selected subject.
- Added multi-step query synthesis over successful intermediate results, including passing raw MCP rows and _objectRef values into the next LLM query step.
- Persisted query synthesis result artifacts in conversation context so follow-up questions can reference real MCP objects instead of only assistant text.
- Hardened reference matching for structured identifiers such as document numbers, codes, articles, and GUID-like values: fuzzy prefix matches no longer replace exact object references.
- Added a repeated-partial-query guard so an agent cannot execute the same incomplete query after a partial result.
- Expanded generic 1C metadata search vocabulary for supply/purchase terminology so "поставка/поступление" can discover "ПриобретениеТоваровУслуг" objects in configurations where that is the actual document name.
- Strengthened 1C query review for accumulation register Остатки(): invalid third parameters and non-dimension filter fields are rejected before MCP execution.
- Strengthened raw accumulation register review: inactive movement filters such as НЕ <Алиас>.Активность are rejected before MCP execution.
- Added regression tests for partial document-reference results, repeated partial queries, and similar document numbers such as 0000-000019 vs 0000-000001.

5.0.0-alpha.3
- Added generic CountResult and count_entities transform for questions that can be answered as "retrieve entities, then count them".
- Taught the composer to build plans like EntityRefList producer -> count_entities -> render_table_answer for count requests with semantic filters.
- Added ReferenceValueResolver that resolves string filters for reference/enum fields by querying real field values through MCP and passing the matched _objectRef as a parameter.
- Added deterministic repair for LLM-generated enum literals such as ЗНАЧЕНИЕ(Перечисление.X.Y) when the actual value name is different.
- Strengthened query review to reject unconfirmed enum literals before MCP execution.
- Added tests for generic filtered entity counting, reference/enum resolution, and query synthesis repair.
