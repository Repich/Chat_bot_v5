# Автономная установка на Windows

## Состав поставки

Полный архив `wiicon5-offline-windows-x64-<version>.zip` содержит:

- код WIICON ChatBot 5;
- Windows x64 Python 3.12 embedded runtime;
- исходный набор навыков;
- экземпляр `wiic_bwiki` с локальным снимком документации BWiki;
- installer, supervisor и сценарий применения обновлений.

Доступ к интернету на целевом сервере не требуется. Синхронизация с BWiki на
таком сервере недоступна, но локальный снимок продолжает использоваться для RAG.

## Подготовка конфигурации

Распакуйте архив на компьютере, с которого он будет перенесен на сервер.
Скопируйте `server.env.example` в `server.env` и заполните:

```env
WIICON5_LLM_API_BASE=http://адрес-внутреннего-шлюза/v1
WIICON5_LLM_API_KEY=ключ-или-внутренний-токен
WIICON5_LLM_MODEL=gpt-5.4
WIICON5_MCP_URL=http://127.0.0.1:6003
```

В качестве основной модели можно указать доступную через внутренний шлюз
`gpt-5.4` или `glm-5.2`. Название должно в точности совпадать с идентификатором,
который принимает шлюз.

Секреты находятся только в `C:\ProgramData\WiiconChatBot5\config\.env.wiicon5`
и не попадают в диагностические ZIP или update-пакеты.

## Установка

1. Перенесите распакованный каталог на Windows-сервер.
2. Запустите `install.cmd` от имени администратора.
3. Installer скопирует приложение в `C:\ProgramData\WiiconChatBot5`.
4. Будет создана задача Windows Task Scheduler `WiiconChatBot5` с запуском при старте системы.
5. В Windows Firewall будет открыт входящий TCP-порт `7786`.
6. После успешного старта интерфейс доступен по `http://<адрес-сервера>:7786/`.

Административный токен создается автоматически и сохраняется в
`C:\ProgramData\WiiconChatBot5\ADMIN_TOKEN.txt`. Его нужно один раз ввести в
разделе `Администрирование` web-интерфейса.

Установщик не запускает сервис, если вместо рабочего LLM endpoint остался
пример или не указан ключ. После исправления `server.env` достаточно повторно
запустить `install.cmd`.

## Каталоги

```text
C:\ProgramData\WiiconChatBot5\
  app\current\                 текущий код
  app\rollback\                предыдущая версия
  runtime\                     автономный Python
  config\.env.wiicon5          настройки и секреты
  data\bot_instances\          знания, learned-навыки и traces
  data\diagnostics\sessions\   постоянные журналы сессий
  data\diagnostics\bundles\    ZIP для передачи разработчику
  logs\service.log             stdout/stderr бота
  logs\supervisor.log          запуск и обновления
  updates\inbox\               входящие update-архивы
  updates\applied\             установленные архивы
  updates\failed\              отклоненные архивы
```

## Диагностика

Для каждого `session_id` создается отдельный `events.jsonl`. В нем фиксируются:

- точное сообщение пользователя и время запроса;
- результат агента и путь к run trace;
- тип и traceback необработанной ошибки;
- сообщения, возвращенные web-клиенту.

В настройках чата нажмите `Собрать диагностику`. Интерфейс покажет полный путь
к ZIP и одновременно скачает его в браузере. ZIP содержит диалог, события,
полные trace-каталоги этой сессии, `bot.yaml`, версию, сведения о среде и хвосты
служебных логов. `.env`, ключи и административный токен не включаются.

## Обновление без интернета

Обычный пакет называется `wiicon5-update-<version>.zip` и не содержит Python или
полный снимок BWiki, поэтому подходит для частых переносов.

1. Скопируйте ZIP в `C:\ProgramData\WiiconChatBot5\updates\inbox`.
2. В web-интерфейсе откройте `Администрирование`.
3. Нажмите `Проверить архив`, затем `Установить обновление`.

Вариант без web-интерфейса: запустите
`C:\ProgramData\WiiconChatBot5\apply-update.cmd`.

Supervisor проверит manifest и SHA-256 всех файлов, остановит рабочий процесс,
заменит код и запустит сервис. Если `/health` не ответит за 90 секунд, будет
автоматически возвращена предыдущая версия. Накопленные данные не заменяются.

## Сборка поставки

На компьютере с интернетом:

```bash
python3 scripts/build_offline_release.py
```

Команда создает полный installer и обычный update-пакет в `dist/offline`.
Windows runtime скачивается один раз и затем берется из локального кэша.

Если обновление действительно должно дополнить отсутствующие seed-данные:

```bash
python3 scripts/build_offline_release.py --mode update --include-data-seed-in-update
```

Существующие рабочие данные таким пакетом не перезаписываются.
