# Обзор Проекта

## Что Это

WIICON ChatBot 5 - локальный агент для бизнес-вопросов по данным 1С. Он
работает с неизвестной или частично известной конфигурацией 1С через MCP-сервер
и LLM-провайдера.

Агент получает вопрос на естественном языке, хранит контекст диалога, проверяет,
может ли ответить существующими навыками, и при необходимости пытается построить
безопасный read-only запрос 1С на основе реальных метаданных подключенной базы.

Сейчас это alpha-версия исследовательского и инженерного прототипа. В
репозитории находятся локальный HTTP-сервис, web-клиент для тестирования,
runtime навыков, пайплайн синтеза запросов, интеграция с MCP, тесты и
трассировка.

## Зачем Проект Нужен

Предыдущие версии чат-бота слишком часто скатывались к частным исправлениям:
отдельный обработчик под склад, отдельный обработчик под документ, отдельная
эвристика под конкретную фразу. Для 1С такой подход плохо масштабируется:
конфигурация может содержать сотни объектов, кастомные реквизиты, разные
названия типовых сущностей и множество формулировок одного бизнес-смысла.

Версия 5 строится вокруг другой модели:

- источник истины - вопрос пользователя, контекст диалога и реальные метаданные
  1С;
- имена объектов, реквизитов, ресурсов, измерений и значений перечислений должны
  обнаруживаться или подтверждаться, а не зашиваться в Python-код;
- навыки должны быть атомарными и комбинируемыми;
- если готовых навыков не хватает, агент должен зафиксировать разрыв, построить
  безопасный путь получения данных и в перспективе сохранить его как
  переиспользуемый навык;
- если бизнес-смысл неоднозначен, агент должен уточнить у пользователя, а не
  угадывать.

## Цели

- Отвечать на бизнес-вопросы по WIICON/WIIC/1С через MCP.
- Работать с неизвестной конфигурацией 1С через runtime-поиск метаданных.
- Использовать существующие навыки и компоновать их в планы.
- Создавать новые query-навыки только на базе проверенных метаданных и успешных
  read-only запросов.
- Проверять запросы до выполнения.
- Проверять, что результат действительно отвечает на вопрос пользователя.
- Сохранять подробные трассы, чтобы можно было разобрать ошибку агента, LLM,
  MCP или конкретного запроса.
- Уточнять неоднозначные вопросы.

## Нецели

- Агент не должен изменять данные 1С.
- Агент не должен делать вид, что получил данные, если MCP или метаданные
  недоступны.
- Кодовая база не должна превращаться в набор классификаторов под каждый объект
  1С и каждую пользовательскую фразу.
- Агент не должен сам выбирать между разными бизнес-смыслами, например между
  суммой документа и фактической задолженностью после оплат.
- Web-клиент пока является тестовым интерфейсом, а не production UI.

## Текущий Статус

Текущая версия: `5.0.0-alpha.40`.

Реализована основа:

- локальный HTTP-сервис и web-клиент;
- контекст диалога и история сессии;
- базовые ответы на общие вопросы и отсечение нерелевантных вопросов;
- LLM-декомпозиция цели;
- реестр навыков, граф навыков, composer и runtime;
- получение метаданных через MCP;
- синтез read-only запросов 1С;
- проверка безопасности и корректности запросов;
- проверка достаточности результата;
- состояние уточнения для неоднозначных вопросов;
- хранилище learned skills;
- трассировка каждого запроса;
- регрессионные тесты для текущего пайплайна.
- bot instance профиль, который отделяет тексты и доменные настройки конкретного
  бота от ядра агента;
- подключаемые prompt/domain packs для правил 1С и торговых подсказок;
- learned skills в статусе candidate с evidence и metadata dependency contract;
- вычисляемый fingerprint конфигурации при режиме `WIICON5_CONFIG_FINGERPRINT=auto`.
- onboarding pipeline по выгрузке конфигурации, который создает candidates,
  metadata index, semantic dictionary, register usage map и query patterns без
  автоматического утверждения skills/bindings;
- web-admin запуск первоначального обучения и статус `trained/not trained`;
- локальный onboarding metadata index как дополнительный источник поиска
  объектов метаданных рядом с MCP;
- trust/evidence модель метаданных: XML/MCP поля считаются verified, regex
  находки остаются hints и не проходят query review как факты;
- onboarding evidence для query synthesis: реальные query patterns и карта
  движений документов по регистрам из выгрузки конфигурации;
- verifier candidate bindings через MCP перед ручным утверждением bindings;
- regression case tooling из trace;
- composer explainability trace с выбранными и отклоненными candidate skills.

Проект остается alpha-версией. Архитектура проверяется на реальных вопросах и
корректируется по трассам, когда видно неправильную границу ответственности.
